# Scale bug debugging and fixes

> Saved: 2026-04-15

## 这个文档里说的问题还存在，你修一下

- 检查并修复 `ZoomableImage` 的最小缩放比、切图后 slider/fitZoom 同步，以及切图引起的 layout/ChangeView 时序问题。

## 最小缩放比（Bug 1–3）没生效

- 新增 `_minPercentage`（默认 25）。
- 在 `FitToWindow()` 中动态计算 `_minPercentage`（基于 `_fitZoom`），并用它替代硬编码 25。
- 更新 `ZoomSlider.Minimum` 并在修改时用 `_ignoreSliderChange` 保护，`ClampZoomPercent`/`ZoomOutStep` 改为使用实例字段。
- 构建通过，问题 1–3 修复。

## 切图后 slider/fitZoom 不一致（Bug 4–5）

- 发现根因：在切换图片时立即调用 `FitToWindow()` 会在 ScrollViewer 尚未完成 layout/measure 提交前调用 `ChangeView`，导致 ChangeView 被静默忽略；随后 `OnScrollViewChanged` 用旧 ZoomFactor 覆盖了我们设为 100 的 slider 值。
- 初步修复尝试：使用 `DispatcherQueue.TryEnqueue(Low)` 延后 `FitToWindow()`，等待 layout；但该实现中移除 `SizeChanged` handler 导致后续 layout 无法触发回调，未完全解决。
- 回滚了上一步的尝试以便逐步分析。

## 改进策略与实现

- 改为在拿到图片尺寸后立即调用 `EstablishFitZoom(imgW,imgH)`：计算并设置 `_fitZoom`，立即设置 `ZoomSlider.Value = 100` 与 `ZoomPercentText.Text = "100%"`（建立正确的 UI ↔ zoom 映射关系）。
- 为确保 `ChangeView` 在 layout commit 后执行，采用 `FitAfterLayout()`：原实现使用 `SizeChanged` + `TryEnqueue(Low)` 两路触发作为保险，后因 race 条件改为使用 `Scroll.LayoutUpdated` 统一触发，直到 `ExtentWidth/Height > 0` 再执行 `ChangeView`；使用 `_sourceGeneration` 防止旧回调影响新图切换。
- 构建通过。

## 为调试加入日志并定位问题

- 为便于定位，将调试日志写入应用日志（与其他日志统一输出到 `%LocalAppData%\FluentGallery-Dev\logs`），并记录 `EstablishFitZoom`、`TryEnqueue`、`SizeChanged`、`FitToWindow` 等关键点。
- 运行并复现后，发现 TryEnqueue(Low) 在 layout 提交前触发且 `Extent=0x0`，ChangeView 被丢弃；并且初版 TryEnqueue 实现会移除 SizeChanged handler 导致后续真正的 SizeChanged 无法触发。
- 基于日志，最终改用 `Scroll.LayoutUpdated` 来可靠检测 layout 提交并触发 `ChangeView`。

## 清理与收尾

- 问题定位并修复后，应用户要求移除临时日志和调试代码：删除了 `ILogger` 注入、`_logger` 字段及所有 `_logger.LogDebug` 调用，并精简了相关辅助逻辑。
- 构建通过，0 错误。

## 结论与后续建议

- 已修复最关键的 scale / fit / slider 同步问题，并解决了因为异步 layout/ChangeView 导致的状态不同步。

# i18n Progress and Fixes

> Saved: 2026-04-27

## 给项目做一下 i18n。你觉得应该支持哪些常见语言？

这个项目已经有 `zh-CN` 和 `en-US` 两套资源，但界面里还有不少中文硬编码。更合理的顺序是先把现有文案全部抽到资源，再扩语言包。

我建议首发支持 `zh-CN`、`en-US`、`ja-JP`，第二梯队补 `ko-KR`、`de-DE`、`fr-FR`、`es-ES`。

## 好

先从一个页面验证 `x:Uid + Resources.resw` 方案，然后再批量扩到其它页面和资源键。

## 为什么设置里切换英文没生效

根因是设置页只保存了语言值，但应用启动时没有把这个值应用到语言覆盖，所以资源仍按系统语言加载。

我已经在启动阶段补上语言覆盖读取，并通过 `make build` 验证了改动。

## 2026-04-27 17:38:56.457 [FTL] : Unhandled WinUI exception ...

问题出在 `ApplicationLanguages.PrimaryLanguageOverride` 的设置时机太晚。我把语言应用逻辑前移到更早的启动阶段，避免进入无效状态。

`make build` 已通过。现在切换英文后需要完全退出再重新启动，语言才会生效。

## 2026-04-27 17:42:18.892 [INF] ... 没闪退了，但还是中文

日志显示 `Windows.Globalization.ApplicationLanguages` 在当前 WinUI 3 桌面上下文不可用。我改用 Windows App SDK 对应的 `Microsoft.Windows.Globalization.ApplicationLanguages`，并再次通过构建验证。

## 可以了！现在请你为其它页面和 toast 都 i18n 一下

我先补了一个统一的 C# 本地化入口，再把其它页面里的动态文案、toast、确认弹窗和设置页静态文本都接到资源键上。

后续还修过一次 `ResourceLoader.GetForViewIndependentUse()` 的兼容问题，最后再次运行 `make build`，构建成功。

当前结果是：其它页面和 toast 已经完成 i18n，设置页也做了资源化，英文切换后不会再夹杂中文文案。

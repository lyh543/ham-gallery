## User

```md
我想要使用 llm 从零开发一个 windows 平台的相册应用，请帮我编写提示词。

1. 平台：Windows，使用 Fluent UI 开发，类似于 Windows 11 自带的相册
2. 页面：需要有至少以下页面：
  a. 相册列表，展示管理的所有相册，支持创建、删除、重命名相册
  b. 照片列表，展示相册中的照片，支持添加、删除
  c. 照片详情，展示照片。支持全屏。支持照片信息展示（拍摄时间、位置、相机型号等）。支持照片简单的编辑（旋转、裁剪），更复杂的编辑可以调用外部接口。支持照片删除（调用系统 API 移动到回收站）
  c. 全部照片列表，展示所有照片。点击某张照片可以进入照片详情页
  d. 设置页面，支持设置扫描相册（多选、递归）、排除文件夹、语言、删除照片是否需要确认、清除片缓存、清除数据库缓存、清除全部数据等
1. 导航栏：有相册列表、全部照片、设置页面。相册列表页面下可以支持固定/取消固定指定的目录到导航栏，方便用户快速访问
2. 多语言支持：需要支持中文、英文。默认为英文，用户可以在设置中切换语言。
3. 亮点功能：
   1. 使用 Fluent UI 的设计语言，界面美观、现代
   2. 对触屏友好（详情页可以通过触屏放大、缩小照片；列表页可以通过触屏调整每行展示的照片数量）
   3. 支持 jpg、png、bmp、heic、heif 等常见图片格式，支持
   4. 相册列表页面支持多种排序方式（名字、日期、创建时间、修改时间、拍摄时间）
   5. 照片列表页面支持多种排序方式（名字、日期、大小、创建时间、修改时间、拍摄时间、原生排序）。原生排序指的是和 Windows Explorer 的排序顺序保持相同
   6. 在相册列表、照片列表、全部照片页面，通过照片缩略图，加快展示照片。如果照片的修改时间未生变化则重新生成缓存
   7. 在相册列表、照片列表、全部照片页面，将照片信息存到数据库中，不是每次都需要扫描全量的照片。Windows 文件管理器的痛点是每次打开目录都需要重新加载所有相册、然后重新排序，在一千张照片的目录下性能非常非常差。这个每次打开应用时，首先展示数据库里的照片信息，然后后台线程根据设置里需要扫描的目录，进行扫描照片目录，如果照片的修改时间未生变化则不更新数据库，只有当照片的修改时间发生变化时才更新数据库。
   8. 在照片详情页浏览某张图片时，预先加载前后的几张照片的全量数据。
   9. 对于超大的照片，先降采样加载，用户放大照片时再加载图片细节，且需要保证前端不卡顿。
   10. 从 Windows Explorer 打开照片时，保证用户可以向前/向后查看图片，且图片顺序和用户在 Windows Explorer 的排序顺序保持相同。可以自动加载所在目录下的照片，并进入照片详情页。
```
